> 작업할 때마다 이어서 적어요. 맨 아래 **용어 풀이**도 함께 봐 주세요.
>
> 마지막 갱신: 2026-11-12

## 2. 결정 사항과 이유

### ① 프로그램을 claude.ai 밖으로 옮기기 (2026-11-12)
- **결정:** 저장은 **Supabase**, 화면(웹 주소)은 **Netlify**에 올려요.
- **이유**
  - 지금은 사장님 claude.ai 계정으로 로그인해야만 열려요. 계정이나 claude.ai 사정에 따라 프로그램 전체가 멈출 수 있어요.
  - 다른 사람에게 넘기거나 기능을 늘리기 어려워요.
  - 이미 운영 중인 **장부 프로그램과 같은 방식**이라 관리 방법을 하나로 맞출 수 있어요.
- **바뀌는 점:** 사장님은 새 주소에서 이메일과 비밀번호로 로그인해요. 화면과 기능은 거의 같아요.

### ② 장부 프로그램과 같은 저장소를 함께 쓰기 (2026-11-12, 변경됨)
- **처음 결정:** 개인정보를 확실히 나누려고 저장소(Supabase 프로젝트)를 장부와 **따로** 만들려고 했어요.
- **바뀐 결정:** 장부가 쓰고 있는 저장소 **안에 타임카드를 함께** 넣어요.
- **바꾼 이유: 비용**
  - Supabase 유료(Pro) 요금 월 25달러는 '조직' 요금이에요. 그 안에 저장소 **1개분**이 포함돼 있어요.
  - 저장소를 하나 더 만들면 **하나당 월 약 10달러가 추가**돼요. 같이 쓰면 **추가 비용이 0원**이에요.
  - 타임카드는 사용량이 아주 작아서 장부와 합쳐도 유료 요금제 포함량의 몇 % 수준이에요.
- **대신 이렇게 안전장치를 넣었어요** (②-1, ②-2 참고)
  - 타임카드 자료에는 이름 앞에 모두 'tc'를 붙여서 장부 자료와 섞이지 않게 했어요.
  - **'타임카드 권한'이 있는 계정만** 타임카드 자료를 볼 수 있어요. 장부용 계정으로는 직원 급여나 주민번호를 볼 수 없어요.
- **알아 두실 점 (같이 쓰기 때문에 생기는 것)**
  - **되돌리기가 묶여요.** 저장소의 '날짜로 되돌리기' 기능은 장부와 타임카드를 **통째로** 되돌려요. 타임카드를 어제로 되돌리면 장부의 오늘 거래도 사라져요. 그래서 타임카드 실수는 통째 되돌리기 대신 **변경 이력이나 백업 파일로 그 부분만** 고쳐요.
  - **반대 방향은 아직 열려 있어요.** 장부는 원래 "로그인한 사람이면 누구나" 볼 수 있게 되어 있어요. 그래서 타임카드 전용 계정을 새로 만들면 그 계정으로 장부를 볼 수 있어요. → **관리자 계정 하나로 둘 다 쓰기로 해서(⑦) 지금은 문제없어요.** 나중에 직원 등 다른 사람에게 따로 계정을 줄 일이 생기면 그때 장부 쪽에도 권한 확인을 추가해야 해요.

### ②-1 이름 규칙: 타임카드 자료는 'tc'로 시작 (2026-11-12)
- **결정:** 타임카드가 저장소에 만드는 것(표, 사진 보관함, 서버 프로그램, 비밀값)은 **모두 이름이 'tc'로 시작**해요. 예: `tc_docs`(타임카드 자료), `tc-photos`(출퇴근 사진), `tc-notyet-check`(미출근 알림).
- **이유**
  - 장부에 이미 같은 이름(변경 이력 표 `audit_log` 등)이 있어서, 그대로 두면 **설치가 실패하거나 장부 자료를 건드릴 수 있었어요.**
  - 관리 화면에서 어느 프로그램 것인지 한눈에 구분돼요. 나중에 둘 중 하나를 옮기거나 지울 때도 안전해요.
- **장부 쪽은 하나도 바꾸지 않았어요.**

### ②-2 타임카드 권한이 있는 계정만 들어오기 (2026-11-12)
- **결정:** 계정마다 "타임카드 사용 가능" 표시를 붙이고, 이 표시가 있는 계정만 타임카드를 열 수 있어요.
- **이유:** 저장소를 장부와 같이 쓰면서 로그인 계정도 공유되기 때문이에요. 장부용 계정이 타임카드의 개인정보를 보지 못하게 막아요.
- **화면:** 표시가 없는 계정으로 로그인하면 "타임카드 권한이 없는 계정이에요"라는 안내와 로그아웃 버튼이 나와요.
- **설정:** 표시는 관리자가 저장소 관리 화면에서 한 번 붙여요. 사장님이 장부에서 쓰는 계정에 붙이면 같은 계정으로 둘 다 쓸 수 있어요.

### ③ 데이터는 지금 모양 그대로 옮기기 (2026-11-12)
- **결정:** 저장되는 데이터 구조를 바꾸지 않고 그대로 옮겨요.
- **이유:** 이미 쓰고 있고 시험까지 마친 **급여·근무 계산 부분을 건드리지 않으려고**요. 고치는 곳이 적을수록 새 오류가 생길 위험도 줄어요.

### ④ 메일 기능은 잠시 꺼 두기 (2026-11-12)
- **결정:** 휴대폰 메일 알림, 세무사 메일 발송, 계약서 사본 메일은 **당분간 쓸 수 없어요.**
- **이유:** 이 기능들은 claude.ai가 대신 Gmail로 보내 주던 기능이라 그대로 옮길 수 없어요. 따로 메일 발송 서비스를 붙여야 해요.
- **대신:** 세무사 전달 내역은 **'문자용 복사'**로 카톡이나 문자에 붙여 넣을 수 있어요. 계약서는 인쇄하거나 파일로 저장할 수 있어요. 미출근 알림은 ⑨의 슬랙으로 대신해요.
- 누르면 "메일 보내기는 아직 준비 중이에요"라고 안내해요.

### ⑤ 예전 출퇴근 사진은 옮기지 않기 (2026-11-12)
- **결정:** 옮기기 전에 찍힌 얼굴 사진은 가져오지 않아요.
- **이유:** 프로그램의 백업 파일에 사진이 들어 있지 않아요. 크기 때문에 원래 빠져 있었어요.
- **영향:** **출퇴근 기록(시각, 근무시간, 급여 계산)은 모두 옮겨져요.** 옛 기록의 사진 칸만 '사진 없음'으로 보여요. 옮긴 뒤 새로 찍는 사진은 정상으로 저장돼요.

### ⑥ 태블릿과 휴대폰 화면이 바로 맞춰지게 유지 (2026-11-12)
- **결정:** 태블릿에서 출근을 찍으면 사장님 휴대폰에 **새로고침 없이 1~2초 안에** 보이는 기능을 그대로 살렸어요.
- **이유:** 원래 프로그램이 이렇게 동작했어요. 사장님 화면의 출근·퇴근 알림과 소리도 이 기능에 기대고 있어요.

### ⑦ 로그인 방식 (2026-11-12)
- **결정**
  - **장부와 타임카드 모두 같은 관리자 계정 하나로 로그인해요.** (2026-11-12 확정: 두 프로그램 모두 관리자용이라 통일)
  - 사장님 계정 **하나**로 태블릿과 휴대폰 모두 로그인해요. 기기마다 **한 번만** 로그인하면 계속 유지돼요.
  - 아무나 가입할 수 없게 **회원가입은 막아요.** 계정은 관리 화면에서만 만들어요.
  - 사장님 화면 → 직원·설정 맨 아래에 **로그아웃** 버튼을 넣었어요. 실수 방지를 위해 두 번 눌러야 돼요.
- **주의:** 사장님 화면에 들어가는 **관리 번호가 기본값 '0000'이면 꼭 바꿔 주세요.** 가게 태블릿은 로그인된 상태로 두기 때문에, 직원이 사장님 화면(급여, 주민번호)에 못 들어가게 막는 건 이 번호예요.

### ⑧ 인터넷이 잠깐 끊겨도 출퇴근 기록이 사라지지 않게 (2026-11-12)
- **결정:** 와이파이가 끊긴 상태에서 찍은 출퇴근은 **태블릿에 잠시 보관했다가, 연결되면 자동으로 서버에 보내요.**
- **화면 표시:** 보내지 못한 기록이 남아 있으면 화면 위에 "아직 서버에 보내지 못한 기록이 N건 있어요"가 떠요.
- **예외:** 사진은 크기 때문에 보관하지 않아요. 그때는 사진 없이 기록만 남아요.
- **주의:** 그 안내가 떠 있을 때 태블릿 데이터를 지우거나 로그아웃하면 그 기록은 사라져요.

### ⑨ 미출근 알림은 슬랙으로 (알림톡은 보류) (2026-11-12)
- **결정:** 정해진 출근 시각에서 지각 봐주는 시간(기본 5분)이 지나도 출근 기록이 없으면 **슬랙으로 알려요.** 카카오 알림톡(뿌리오)은 나중에 필요하면 붙여요.
- **확정:** 사장님 슬랙 사용 가능 확인 (2026-11-12)
- **연결 완료 (2026-11-12):** 슬랙 채널에 알림 앱(Incoming Webhook)을 연결했고, 앱의 '시험 알림 보내기'로 메시지가 오는 것을 확인했어요.
  - 슬랙 알림 주소는 서버 비밀값으로만 저장했어요 (프로그램 파일에는 없음). 이 주소를 아는 사람은 그 채널에 메시지를 보낼 수 있으니, 혹시 밖으로 새면 슬랙 앱 관리 화면에서 주소를 새로 발급하고 알려 주세요.
  - **'슬랙 알림 켜기'는 데이터를 옮긴 뒤에** 눌러요. 지금 켜면 가게 설정이 먼저 저장돼서 옮길 때 섞여요.
- **받는 곳 결정 (2026-11-12): 대표님 슬랙 워크스페이스로 옮겨요.**
  - 지금은 작업자가 시험용으로 연결한 워크스페이스로 와요.
  - 이관 전에 대표님 워크스페이스에서 알림 채널과 연결 주소(Webhook)를 만들고, 서버 설정만 그 주소로 바꾸면 돼요. 프로그램을 다시 올릴 필요는 없어요.
  - 대표님께 부탁: 슬랙 계정·워크스페이스 준비, 알림 받을 채널 만들기 (연결 작업은 작업자가 안내)
  - **진행 (2026-11-13):** 새 워크스페이스에 알림 앱을 만들고 서버 설정을 새 주소로 바꿨어요. 남은 것: 새 채널로 시험 알림이 오는지 확인 → 예전 워크스페이스의 앱 삭제
- **비교해 본 내용**

| | 슬랙 | 카카오 알림톡 (뿌리오) |
|---|---|---|
| 준비 기간 | 당일 | 며칠 (카카오 비즈니스 채널 개설 + 문구 **카카오 심사**) |
| 비용 | 무료 | 건당 요금 + 아래 문제 때문에 **월정액이 추가될 수 있음** |
| 문구 바꾸기 | 바로 | 바꿀 때마다 다시 심사 |
| 받는 곳 | 사장님이 **슬랙 앱을 설치**해야 함 | 이미 쓰는 카카오톡 |

- **알림톡이 어려운 이유 (쉽게)**
  - 문자·알림톡 회사는 보안 때문에 **"미리 등록한 주소(IP)에서 온 요청만 받는"** 경우가 많아요.
  - 우리가 쓰는 서버는 요청할 때마다 이 주소가 바뀌어요. 그래서 등록할 수가 없어요.
  - 해결하려면 **주소가 고정된 중간 서버를 빌려야** 하고, 매달 요금이 나가요.
  - 뿌리오가 정말 이 등록을 요구하는지는 뿌리오에 문의해서 확인이 필요해요. 요구하지 않으면 훨씬 쉬워져요.
- **나중에 알림톡으로 바꾸려면:** 알림을 판단하는 부분은 그대로 쓰고 **보내는 부분만 바꾸면** 돼요. 처음부터 다시 만들 필요가 없어요.

### ⑩ 미출근 확인은 태블릿이 아니라 서버가 하기 (2026-11-12)
- **결정:** 서버가 **5분마다** 직접 확인해요. 같은 직원은 **하루에 한 번만** 알려요.
- **이유:** 원래는 가게 태블릿이 켜져 있어야 확인하는 방식이었어요. 그런데 태블릿이 꺼지거나 와이파이가 끊긴 날이 오히려 알림이 꼭 필요한 날이에요.
- **확인한 것:** 서버의 판단이 프로그램 화면의 '미출근' 표시와 **똑같은지** 하루 전체를 7분 간격으로 비교하는 시험을 만들어 통과했어요. 휴무 처리, 퇴사자, 입사 전, 야간 근무도 포함했어요.
- **한계:** 태블릿 인터넷이 끊긴 사이에 찍은 출근은 서버가 아직 모를 수 있어요. 그래서 **실제로는 출근했는데 알림이 갈 수도 있어요.** 알림 문구에 이 안내를 넣어 뒀어요.

### ⑪ 프로그램 코드 보관함(GitHub)은 공개로 유지 (2026-11-12)
- **결정:** 코드를 올린 GitHub 저장소(`dajoba-team/timecard`)는 **누구나 볼 수 있는 공개 상태**로 둬요.

### ⑫ 인터넷 주소 만들기와 접속 보호 (2026-11-12)
- **주소:** https://dajoba-timecard.netlify.app (Netlify 기본 주소)
- **지금은 보호가 두 겹이에요**
  1. Netlify의 **사이트 보호**: Netlify 팀 멤버만 사이트를 열 수 있어요. 로그인 안 한 사람은 화면 자체가 안 보여요.
  2. **타임카드 로그인과 권한**: 사이트에 들어와도 타임카드 권한이 있는 계정으로 로그인해야 자료가 보여요. 로그인 없이 자료를 요청해 보니 아무것도 안 나오는 것을 확인했어요.
- **결정:** 아직 아무도 안 쓰니 1번 보호는 **이관하는 날까지 켜 둬요.** 이관 당일 태블릿을 바꾸기 직전에 풀어요. 안 풀면 가게 태블릿과 사장님 휴대폰도 Netlify 계정이 있어야 열 수 있어서 쓸 수가 없어요. 풀어도 2번 보호(타임카드 로그인)는 그대로예요.
- **회사 주소(커스텀 도메인):** Netlify를 최종적으로 어느 계정에 둘지 정한 뒤, 이관 1~2일 전에 연결해요.
- **변경 (2026-11-12 오후):** 운영 주소는 Netlify 보호를 풀어 **공개(Public)**로 바꿨어요. 대표님께 작업물을 보여 드리기 위해서예요. 로그인 없이는 여전히 타임카드 로그인 화면까지만 보이고, 자료는 보이지 않아요.
- **변경 (2026-11-13): Netlify는 대표님 계정에 새로 만들어요.** 작업자 계정에 만든 시험용 사이트는 새 사이트를 확인한 뒤 지워요.
  - 이유: 프로그램 주소를 작업자 개인 계정이 아니라 대표님 쪽에서 관리하기 위해서예요.
  - 그래서 **최종 주소는 새 사이트 주소**예요 (위 주소는 시험용). 태블릿에 저장할 주소라 이관 전에 이름을 확정해요.
- **최종 주소 확정 (2026-11-13): https://timecard.dajoba.kr** — 회사 도메인에 연결했어요. 보안 연결(HTTPS) 인증서도 자동으로 발급됐고, 로그인 화면이 정상으로 뜨는 것을 확인했어요. 가게 태블릿과 사장님 휴대폰에는 이 주소를 저장해요.
  - 무료 요금제면 화면 오른쪽 아래에 'Powered by Netlify' 표시가 붙어요. 유료면 설정에서 끌 수 있어요.

### ⑬ 운영 중인 최신판(v15) 반영과 저장 방식 유지 (2026-11-13)
- **알게 된 것:** 이전 작업을 시작한 기준은 **버전 11**이었는데, 그사이 claude.ai에서 **버전 15**까지 올라갔어요. 사장님이 지금 쓰는 건 v15예요.
  - v12 위치 확인, v13 외근 직원 예외, v14 가게 양식 근로계약서, v15 탭 순서
- **결정 1 — 새 프로그램에 v12~v15를 합쳐요.** 이관한 뒤에도 사장님이 쓰시던 기능과 화면이 그대로여야 하니까요.
  - 미리 합쳐 보니 겹치는 곳이 한 줄뿐이었고, 기능 시험 14개가 모두 통과했어요.
  - 위치 확인을 쓰려면 사이트 보안 설정에서 **위치 사용을 허용**해야 해요 (지금은 막혀 있음). 태블릿에서 처음 한 번 '위치 허용' 창이 떠요.
- **결정 2 — 저장 방식은 지금 만든 방식을 그대로 써요.** 인수인계 자료에 다른 방식의 설계안(가게·직원·기록을 표로 잘게 나누는 방식)이 들어 있었어요.
  - 이유: 지금 방식은 이미 설치·시험·배포까지 마쳤고, 받은 백업 파일도 그대로 옮길 수 있어요. 바꾸면 처음부터 다시 만들고 다시 시험해야 해요.
  - 설계안의 좋은 아이디어는 아래 '나중에 개선할 것'으로 남겨요.
- **나중에 개선할 것 (지금은 안 함)**
  - **개인 번호(PIN) 확인을 서버에서 하기:** 지금은 태블릿이 직원 번호를 받아서 확인해요. 서버에서 확인하면 번호가 기기에 내려오지 않아 더 안전해요.
  - **사진에 실제 도로명 주소 넣기 (카카오 지도 API):** claude.ai에서는 불가능했지만, 지금 구조에서는 서버 함수로 가능해요. 지금은 '등록한 가게 주소와 거리'를 새겨요.
  - **세무사 매월 자동 발송·미출근 메일을 서버로:** 메일 기능을 다시 붙일 때 같이 (결정사항 ④)

## 5. 확인·준비 부탁드릴 것

1. ~~Supabase 새 프로젝트 결제 승인~~ → **필요 없어졌어요** (장부 저장소를 함께 쓰기로 해서 추가 비용 없음)
   - 타임카드 계정 → **확정: 장부와 같은 관리자 계정 하나로 통일 (2026-11-12)**

3. **옮기는 날 정하기:** 손님이 적고 출퇴근이 없는 시간대가 좋아요. 백업을 받은 뒤 새 주소로 바꾸기 전까지 옛 주소에 찍힌 기록은 빠질 수 있어요.

6. **슬랙:** 대표님 슬랙 계정과 워크스페이스를 준비하고, 알림 받을 채널을 만들어 주세요. 연결은 작업자가 도와드려요 (⑨ 참고).
