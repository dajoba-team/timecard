### 1-2. 커스텀 도메인 연결 (쓸 경우) — **(작업자)**
**언제:** Netlify를 최종 위치(계정·팀)에 둔 뒤, **이관 1~2일 전.**
- 지금 하지 않는 이유: 도메인은 특정 Netlify 사이트에 묶여요. 나중에 사이트를 옮기면 도메인을 떼었다 다시 붙이고 SSL 인증서도 다시 받아야 해서 접속이 잠깐 끊길 수 있어요. Netlify DNS(네임서버 위임)를 쓰면 DNS 설정도 그 계정에 속해서 같이 옮겨야 해요.
- 당일에 하지 않는 이유: DNS가 퍼지고 SSL이 발급되는 데 몇 시간 걸릴 수 있어요.
- 주소는 **한 번만** 정하기: 주소가 바뀌면 태블릿 홈 화면 바로가기와 Supabase Redirect URLs를 다시 바꿔야 해요.

순서
1. Netlify → 사이트 → **Domain management** → **Add a domain** → 예: `timecard.회사도메인.com`
2. 도메인 관리하는 곳(가비아·Cloudflare 등)에서 Netlify가 안내하는 레코드 추가 (보통 서브도메인은 **CNAME → `<사이트이름>.netlify.app`**)
3. Netlify에서 **HTTPS 인증서 발급 완료(Provision certificate)** 확인
4. 새 주소로 열어서 로그인 화면이 뜨는지 확인
5. Supabase 장부 프로젝트 → Authentication → URL Configuration → **Redirect URLs**에 새 주소 추가

### 2-4. 옮기기 + 자동 검증 — **(Claude 또는 작업자)**
처음 옮길 때:
```bash
node scripts/import.mjs backups/타임카드_백업_YYYY-MM-DD_HHMM.json
```
- 마지막에 `✅ 검증 통과: 파일과 서버 데이터가 일치해요`가 나오면 성공

이런 메시지가 나오면:

| 메시지 | 뜻 | 할 일 |
|---|---|---|
| `❌ 서버에 이미 문서 N개가 있어요` | 전에 예행연습으로 옮겼거나, 새 화면에서 뭔가 저장됨 | 새 백업으로 바꾸는 게 맞으면 아래 `--force`로 다시 실행 |
| `❌ 서버 접속 실패` | `.env` 값이 없거나 틀림 / 인터넷 문제 | `timecard/.env`에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 확인 (장부 `.env`와 같은 값) |
| `❌ 검증 실패 - 누락/내용 다름` | 일부가 제대로 안 들어감 | 같은 명령을 `--force`로 한 번 더 실행. 그래도 실패하면 멈추고 기존 프로그램 계속 사용 |

예행연습 뒤 최신 백업으로 바꿀 때 (또는 위 표에서 `--force` 안내가 나온 경우):
```bash
node scripts/import.mjs backups/타임카드_백업_YYYY-MM-DD_HHMM.json --force
```
- 새 백업 내용으로 덮어쓰고, 새 백업에 없는 문서(그사이 기존 프로그램에서 지운 것)는 삭제 표시해요
- 서버가 스스로 쓰는 기록(슬랙 알림 결과·중복 방지 표시)은 건드리지 않아요

서버와 다시 비교만 하고 싶을 때:
```bash
node scripts/import.mjs backups/타임카드_백업_YYYY-MM-DD_HHMM.json --verify
```

**가게 태블릿**
1. 새 주소 열기 → 관리자 계정(장부 로그인 계정)으로 로그인 (한 번만 하면 계속 유지)
2. 브라우저 메뉴 → **홈 화면에 추가** (앱처럼 전체 화면으로 열림)
3. '출퇴근 화면' 상태로 두기. **'이 기기는 사장님 기기로 기억하기'는 체크하지 않기**
4. 사진 인증을 쓰면: 직원 한 명으로 시험 출근 → 카메라 허용 → 사진이 찍히는지 확인 → 그 시험 기록은 사장님 화면 → 출퇴근 기록에서 지우기

**사장님 휴대폰**
1. 새 주소 열기 → 같은 계정 로그인 → 사장님 화면 → '이 기기는 사장님 기기로 기억하기' 체크
2. 태블릿에서 시험 출근을 찍었을 때 휴대폰 현황에 1~2초 안에 뜨는지 확인

### 2-7. 마무리 설정 — **(사장님)**
1. **관리 번호 바꾸기**: 사장님 화면 → 직원·설정 → '가게 설정' 칸의 **고치기** → '사장님 관리 번호 4자리'를 0000에서 다른 번호로 → 저장
2. **슬랙 알림 켜기**: 현황 탭 → 💬 슬랙 미출근 알림 → **슬랙 알림 켜기**
   - **이관이 끝난 뒤에만** 켜기. 먼저 켜면 기존 프로그램에서 출근한 직원도 '미출근'으로 알림이 가요
3. 직원들에게 "이제 새 태블릿 화면에서 출퇴근" 안내
4. 기존 claude.ai 프로그램은 **바로 지우지 말고** 1~2주 그대로 두기 (문제 생기면 돌아갈 수 있게). 대신 출퇴근은 새 화면에서만

### 2-8. 기록 — **(Claude)**

## 3. 문제가 생기면 (되돌리기)

| 상황 | 할 일 |
|---|---|
| 옮기기 검증이 계속 실패 | 이관 중단. 기존 claude.ai 프로그램 계속 사용. 서버 데이터는 다음에 `--force`로 다시 옮기면 덮어써짐 |
| 새 화면 숫자가 기존과 다름 | 새 화면에서 고치지 말고 기존 프로그램 계속 사용. 작업자가 원인 확인 |
| 이관 후 며칠 쓰다가 큰 문제 | 기존 프로그램으로 돌아가기 가능 (지우지 않았으면). 단 새 화면에서 찍은 기록은 기존 프로그램에 없으니 따로 옮겨 적어야 함 |
| 슬랙 알림이 잘못 감 | 현황 탭에서 '슬랙 알림 끄기' → 작업자에게 알리기 |
| 태블릿 인터넷이 끊김 | 기록은 태블릿에 잠시 보관됐다가 자동 전송 (화면 위에 'N건 대기' 표시). 그동안 태블릿 데이터 지우기·로그아웃 금지 |

**장부에는 영향이 없어요.** 타임카드 자료는 모두 `tc` 이름으로 따로 있고, 옮기기 스크립트는 `tc_docs`만 건드려요.
단, Supabase의 '날짜로 되돌리기(백업 복원)'는 장부까지 같이 되돌리니 **쓰지 마세요.**
